# 正式数量接入评估与实施方案

2026-11-04。**本阶段只提交设计与缺口清点，等待独立评审；没有实施正式数量接入、解除门禁或迁移。**

## 1. 当前边界

采购/质检/放行/入库演示与审计数量资格是两套保证。人工声明实际日期并记录岗位动作，不等于正式审计采信。质量放行不决定F/T/W期间、份额、容量或历史资格。

公开evaluate_delivery_scope、summarize_delivery_facts继续quantity_contract_not_ready。内部两个V2 candidate路径仍synthetic_only、formal_eligible=False；本方案不加客户端ready开关或旧算法回退。原242方法/585subTest不折算为149项完整规格通过，原89项历史后端迁移/运行、真实来源/审批和C02仍需独立验收。

## 2. 后续输入和固定契约

沿用audit_delivery_contract.QuantitySnapshot及prepare_quantity_snapshot。操作区分独立事实汇总与订单明细计算，前者不强补订单或输出份额结论，后者必须有明确目标范围。版本使用现有完整V2标识，不由context或客户端布尔补选。

完整保留raw_capture、原槽位、WP1问题、拒采信对象和定位，不过滤坏记录重建清单。内容绑定包括事实/份额及版本、数量/单位、日期值/精度/时区、关系状态/版本、证据、决定、覆盖集合和观察上下文；同清单标签不等于同内容。准备后类型、存在性或内容变化拒绝。

K=(含事实版本的parent_fact_ref, partition_version, fragment_id)。同键不同内容冲突，定义/引用分离，不因多引用加量；历史关系不占当前；跨分区没有组合依据不得拼接。Decimal保留精度，不舍入容量微差、不改全局精度，不执行不可信比较钩子。

现有Float累计、OCR匹配、人工日期及IQC抽检/放行都不能直接构造正式“已验证”快照。须先有受控来源、字段决定和覆盖依据，并保留原记录与规范候选。

## 4. 期间、容量和数量组织

先做不依赖期间的类型/身份/数值/区间检查，再按可靠日期归期。仅全部因果来源可靠期后且只影响当期纳入/容量才排除当前影响；完整清单/图继续保留，混合来源或独立工作流限制仍适用。

F=核实物理量，T=数量、期间及目标明细归属均具备资格的本期量，W=计算纳入量。日期可靠但订单/明细归属未知的80保留在F及待核维度，不进入T；独立事实汇总不输出T/W。沿用W=Cc+Rr+Ep、T=W+Z、Pp=Ep+Z、verified_assigned=Cc+Rr。交叉维度不横向相加；待恢复不重复进入Pp，未知不强算本期，W减少不能恢复原整行余额。

capacity_status明确feasible/infeasible/undetermined，与demand_period_status分别表达。可靠子约束可证明违反，即使另有日期未知；子检查通过不能证明整个未知分量可行。保留未知候选/容量节点、可靠预占及原需求，不删节点拆独立分量，不借W过滤掩盖超配。容量不产生分配或审批，不用FIFO/比例自动分配。

## 5. 逐指标与计日

沿用value/status/reasons/basis_refs/scope_ref/coverage。子集用verified_subset，子集0不证明全量0。按根拒绝→不适用→有据常量→业务前提不足→能力未实现→计算的既定顺序，保留全部原因，区分阻断与披露。

业务缺证=undetermined；有效工作日历完整但算法缺失=unsupported/capability，不冒称缺日历或退用自然日。自然日、合同例外、日历版本/范围、具体时刻必须绑定。完整工作日及特殊计日未实现。可靠余额/自然日账龄不被无关逾期能力污染；可靠全量余额0可适用常量/不适用，局部0不够。
